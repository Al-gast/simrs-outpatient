# v1.1.0 — Final QA & Release candidate

Baseline: cumulative v1.0.4 source; upgrade target original v1.0.0. Source release candidate, not a validated production release. All changes from v1.0.1–v1.0.4 retained. No new package dependency, endpoint, schema or migration. The existing migration 000004 remains required.

## Final review fixes

- Auth: older tab with a stale bearer previously could revoke another account's cookie on browser logout. Explicit bearer now takes priority; when it differs from the cookie, preserve that cookie and revoke only the supplied bearer. Restore 401 no longer sends Set-Cookie deletion (a late response could clear a newer session). Invalid cookies remain unusable and expire. Token version revokes all sessions of the authenticated user as before; different-account sessions are not revoked through a stale bearer. Browser login generation markers (random non-secret values, no token/profile stored) invalidate older tabs locally; older tabs cannot suppress shared restore on 401. Duplicate form submission guard. This is a best-effort browser coordination layer, not authorization; storage-disabled or simultaneous cross-tab network races still require separate browser profiles for distinct roles. Cookie-origin and bearer validation remain authoritative.
- Seed MRN: PostgreSQL lpad previously truncated sequences longer than six digits; use dynamic minimum width and one sequence call for the dummy patient. Existing data is not changed by this code; seed must not run during UAT upgrade.
- QA runner: separate sequential Compose build from service start, reduces Mac 8 GB build pressure. Retain existing free-port guard and isolated project cleanup. Expanded stale-bearer/cookie HTTP tests; not executed here.
- Release checks: static method/path validation of all Postman requests against Yii/Node route definitions; syntax-check JS collection scripts, JSON and Python. These checks do not execute Postman or verify response bodies at runtime. Add read-only business fingerprint SQL and explicit no-reseed upgrade guide.

## BR-001 and BR-002 decision

- BR-001 (warning outside practice time): deferred, non-blocking UX enhancement. Current UI already states same-day registration is allowed before practice and backend verifies day and active schedule, not clock. Warning would need a clear definition of end/start time, timezone and business exception; not an assignment prerequisite. Do not reject valid same-day arrivals after hours in this RC.
- BR-002 (future appointments): deferred; would require explicit date request and scheduling validation, date-aware queue/start rule, compatibility and new concurrency/regression tests. Retain current same-day WIB contract; server rejects unknown visit_date input. No hidden appointment support.
- Prioritize submission integrity, runtime retest and evidence. Reassess after release instead of introducing late unverified changes.
