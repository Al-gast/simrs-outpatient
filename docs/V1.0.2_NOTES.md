# SIMRS Outpatient v1.0.2 — Global UI/UX Refinement

## Release status and basis

Cumulative source release, based on `simrs-outpatient-v1.0.1.zip` and `docs/UAT_BACKLOG.md`, with the UAT decisions recorded in conversation. v1.0.0 had actual MacBook runtime/UAT evidence; v1.0.1 and v1.0.2 have not been run on the MacBook. No new screenshots, browser pass results, or performance claims. The same white sidebar, teal palette, light surfaces, typography and design tokens are retained.

## Implemented presentation changes

| Scope | Change |
|---|---|
| Master Data navigation (UI-004/014) | Single collapsible parent, seven text-only children for admin; role-specific allowed subset for other roles; parent opens when entering a master route; active route highlighted. Collapsed desktop exposes a dropdown, mobile uses existing left menu drawer. No cashier master menu. Route and permission policy unchanged. |
| Centered modal (UI-008) | Shared `CenterModal` for master create/edit/detail, stock adjustment, registration, visit detail/history, ancillary detail and user create/edit. Simple forms are centered with scrollable body and footer; master CRUD two columns on desktop and one column on small screens. Mask click does not dismiss. Existing close, confirm, pending and retry handlers retained. Clinical and billing workspaces intentionally remain large drawers until v1.0.3. |
| Icon action (UI-011) | Shared `IconAction`, keyboard focus/hover tooltip and accessible labels. Master details, edit, activation, stock and delete; visit detail/history; ancillary and billing details; user edit/reset. Important business actions (start exam, submit, dispense, pay, print) retain explicit labels. User reset/status split and audit detail are v1.0.4. |
| Currency (UI-032) | `RupiahInput` displays `150.000` but form/API value is string `150000`; exact string formatting, no Number conversion. Accepts unambiguous Indonesian grouping on paste; rejects decimal, alphabetic, negative, malformed and over-limit values via unchanged validation. The strict payment policy still consumes digits-only; existing idempotency payload/key, balance checks and revision guards retained. |
| Date and time (UI-006/020) | `dateLabel` for ISO calendar dates; `dateTimeLabel` for timezone-aware instants rendered in Asia/Jakarta. Native date inputs retain ISO values and browser-native locale appearance; date filters unchanged. Missing/invalid values use em dash. |
| Badge (UI-027/039) | Shared status-to-color mapping; natural-width tags in cards/tables; visible labels retained. |
| Form and search (UI-005/007/016/017/025/028) | Larger search inputs, responsive filter wrapping, contextual placeholder/help text, clickable master-patient link, password guidance, result/dose/frequency examples. Search behavior and server parameters unchanged. |
| Delete context (UI-009) | Stock warning only appears for medicines; permanent deletion semantics from v1.0.1 unchanged. |
| Stock adjustment (UI-013) | Explicit add/subtract controls with positive quantity and preview. The request still contains signed integer `delta`, reason and same idempotency key. Negative projection warns; server validates actual stock. During uncertain retry, hide preview and freeze input; retry reuses stored body/key. |
| Misc (UI-001/002/003/015/029/030/042/044/045/048/049) | Teal links, clearer reporting/monitoring copy, lighter success alert, contextual empty states, line breaks in clinical lab results, less technical pagination copy, add/reload icons, password help. |

## Deferred, not implemented here

- v1.0.1 runtime verification remains pending. No changes to authentication implementation, backend or DB migrations in v1.0.2.
- v1.0.3: dedicated doctor/billing pages, guided review/finalization (UI-018/022), contextual completed clinical messages (UI-023), full dosage/frequency/unit conventions, number presentation (UI-026), Rx subtotal/total (UI-031), invoice ordering, payment progress and print design (UI-033–036). Preserve actual identifiers.
- v1.0.4: chart/report drill-down modal (UI-037–043), role selection/tenaga medis name and separate account operations (UI-046/047/050), audit filter and detail redesign (UI-051–057). Existing drill-down below viewport is not solved by this phase.
- BR-001/002: out-of-hours warning and future appointment date selection were recorded but are not implemented. Registration remains same-day WIB. These require a distinct business-policy decision and backend/frontend tests; do not imply they are part of the UI-only phase.
- Full browser/keyboard/mobile/print checks, actual Postman and runtime QA remain release gates. No new dependencies added. The frontend package version is bumped; unchanged Node package retains v1.0.1.

## Validation

See `evidence/v1.0.2-static-checks.txt` for actual execution. Static suite includes existing PHP and TypeScript policies and new presentation assertions; frontend syntax checking is not dependency-backed typechecking. Full production build was attempted and blocked by missing `vite/client` dependency. Docker, Composer and PostgreSQL not available in authoring environment. No dependency-backed Vitest execution or live browser screenshots. Full Docker build/regression and targeted UAT on MacBook are deferred by user request until final cumulative update.

## Upgrade

No new migration in v1.0.2; v1.0.1 migration 000004 still required if upgrading from original v1.0.0. Do not reset existing data. See `UPGRADE_V1.0.1.md`; the final v1.1.0 cumulative patch will include all changes. Keep the original `.env`, volume and Compose project name, back up first, verify patch against local fixes, and never use `down -v` against the main project. This version is not production-ready medical software.
